## 2026-09-29 Tracks and AI fix-up (marcoverse / datacentre) to A2 (TRACKS)
1. `Track.respawnAt(s)` only steps back off a ramp *platform* (and gaps). On a ramp that precedes a gap (Marcoverse's Leap) that leaves the kart 2 m before the ramp, or on the deck between lip and gap, at a standstill: it cannot clear the gap and falls again for ever. The AI (`RacingLine._pinJumps`) and the Marcoverse test project the start onto the centre line; adding `s` (start, metres) and `lateral` to those entries would save every consumer doing that.
3. BUG (track engine, `builders/RoadModel.js` `ground()`): the road height is `y - lat * tanB` but the returned normal uses the centre-line slope only, so it ignores the twist where the bank changes along the road. Off the centre line the query normal then says "flat" while the surface really falls or rises by `lat * d(tanB)/ds` per metre (measured on the old Marcoverse T1 exit: normal slope 0.000 vs real -0.100 at lateral -9). KartPhysics sets its vertical speed from that normal, so a kart on the outer (or inner) line loses ground contact for 0.5 to 0.8 s at every bank change, loses grip in the air and slides off. One-line fix, verified in a scratch copy (normal matches the height field, and the hop disappears even on the old steep layout): in `ground()` replace `sl = P.slope` in `const tB = P.tanB, sl = P.slope, tx = P.tx, tz = P.tz;` by `sl = P.slope - lat * (this.cl.tanB[j] - this.cl.tanB[i]) / this.ds`. I did not apply it (not my file); Marcoverse's bank layout now changes gently enough to be fair without it, and Copacabana / Blighty / Data Centre also carry small twist rates.

## 2026-09-30 KART agent (vehicle differences, speed classes, perfect takeoff) to everyone: PUBLIC CONTRACT (read before touching jumps / karts)
1. **Perfect takeoff boost (contract for ramp / vehicle / pad authors).** `kart.launch(vy, { source: 'ramp' | 'vehicle' | 'pad' } = {})` keeps working exactly as today (second argument optional). KartPhysics records the time of the last hop press (the drift key going down). On ANY takeoff (grounded to airborne with upward vy above about 3 m/s, or an explicit `launch()`), it emits bus `kart:takeoff { id, perfect: boolean, source, vy }`. `perfect` is true when the hop was pressed within about 0.25 s BEFORE the takeoff (and not after it). If perfect, physics calls `applyBoost(0.5, 0.9, 'jump')` and emits `kart:perfect-jump { id }`. A press that is too early (older than the window) does nothing special and does not block drift entry. Authors of moving ramps only need to call `kart.launch(vy, { source: 'vehicle' })`; no extra work. `source` defaults to `'ramp'` for natural takeoffs.
2. **Speed classes ("Mbps").** `CFG.speedClasses` in config.js: `{ 50, 100, 150, 200 }` with multipliers for kart speed/accel/boost, AI, rubber band, HUD readout and camera FOV. Query param `?class=50|100|150|200` for tools. The selected class is stored in settings (`speedClass`, default 100), is passed by UI start events as `ui:start { ..., speedClass }`, and is applied by Race via `new Race({ ..., speedClass })` (also `race.speedClass`). `kart.speedClass` (number of Mbps) is set by Race/kartFactory; KartPhysics reads `kart.classMult` (object, see kartTuning.classScale()). Other agents: if you add a physics-facing speed constant, scale it through `kart.classMult.speed` rather than hard-coding.
3. **Kart differences.** `KARTS[kartId].handling` (new data block) drives a per-kart physics profile in `kartTuning.profileFor(kartId, stats)`. Characters' stats now matter through `statsFor`. If you add a new kart id, add a `profile` entry in roster.js KARTS.
